# Guía de redacción — CUARTEL-ERP

**Principio fundamental:** el sistema lo usan bomberos voluntarios, no profesionales de tecnología. Las palabras importan. Escribimos **como el CGBVP escribe su propia normativa**, en español peruano estándar, directo y sin jerga técnica.

Esta guía se aplica a **todos los textos visibles para el usuario**: botones, mensajes de error, emails, notificaciones, tooltips, mensajes de ayuda, toasts de confirmación.

---

## 2. Español peruano estándar — no argentinismos ni españolismos

El sistema usa **español peruano neutro, formal pero claro**. No se escribe coloquial, pero tampoco frío.

### Lista de reemplazos obligatorios

| No usar (argentinismos/españolismos) | Usar en su lugar |
|---|---|
| "vos" / "tenés" / "querés" / "podés" | "usted" (formal) o "tú tienes" / "tú quieres" (informal estándar) |
| "acá" | "aquí" |
| "bárbaro" / "genial" / "re bueno" | "correcto" / "listo" / "completado" |
| "dale" | "de acuerdo" · "continuar" |
| "recién" (como adverbio) | "apenas" / "hace poco" |
| "ahorita" (coloquial) | "en este momento" / "ahora mismo" |
| "pa" / "pa'" | "para" |
| "fijate" / "mirá" | "revise" / "observe" |
| "anda" (como interjección) | "vaya" / "diríjase" |
| "vale" / "valer" (españolismo) | "está bien" / "es válido" |
| "ordenador" | "computadora" |
| "móvil" (español = celular en Perú) | "celular" |
| "tío/a" | "señor/a" o el nombre directamente |
| "coche" | "vehículo" / "auto" (según contexto) |
| "aparcar" | "estacionar" |
| "chévere" / "bacán" | mantenerlo formal: "correcto" / "bien" |
| "papeo" / "gluglú" (jergas) | — (nunca en UI) |

### Registro formal peruano que sí usar

- **Usted** como tratamiento default para mensajes institucionales. Para efectivos mayores o cargos altos es importante.
- **Tú** solo en mensajes informales secundarios (confirmaciones rápidas, placeholders). Nunca en emails, alertas importantes, errores críticos.
- En caso de duda entre tú/usted: **usted** siempre gana.

Ejemplo:
- ✅ "Su sesión en el intranet del CGBVP ha expirado. Ingrese nuevamente su usuario y contraseña."
- ❌ "Tu sesión en el intranet expiró, metele de nuevo."

## 3. Microcopy — reglas de escritura

### Errores
Siempre tres partes: **qué pasó · por qué · qué hacer**.

```
[qué pasó] No pudimos descargar el padrón del CGBVP.
[por qué]  El intranet rechazó el usuario y contraseña guardados.
[qué hacer] Revise sus credenciales en Configuración → Sincronización con CGBVP.
```

### Confirmaciones
Antes de acciones destructivas o críticas, escribir la consecuencia explícita:

```
¿Eliminar las credenciales del CGBVP?

Si elimina las credenciales:
· Se detiene la descarga automática de padrón, estado y partes
· Los datos ya descargados se conservan
· Deberá ingresar nuevas credenciales para reactivar la sincronización

[Cancelar]  [Sí, eliminar credenciales]
```

### Tiempos y cantidades
- Tiempos relativos: "hace 3 días", "hace 2 minutos", "ayer a las 14:30"
- Tiempos absolutos importantes: "06 de mayo de 2026, 14:32"
- Cantidades con unidad: "1,247 ítems", "42 bomberos activos", "235 horas de servicio"
- Plazos con tolerancia: "aproximadamente 2 minutos", "en los próximos 15 minutos"

### Acciones (botones y links)
- **Verbos en infinitivo** para acciones: "Descargar plantilla", "Guardar cambios", "Ingresar credenciales"
- **Primera persona plural** para procesos que ejecuta el sistema: "Estamos validando sus credenciales..."
- Nunca "click here" o "haga click". Simplemente nombrar la acción.

### Tono general

| Situación | Tono correcto |
|---|---|
| Bienvenida / onboarding | Cordial, explicativo, formal |
| Confirmación de acción exitosa | Directo, breve, sin florituras |
| Error del usuario | Neutro, orientado a solución |
| Error del sistema | Transparente, con disculpa breve, acción sugerida |
| Alerta crítica (emergencia, vencimiento) | Urgente pero calmado, con acción clara |
| Notificación rutinaria | Informativo, sin drama |

## 4. Ejemplos aplicados

### Pantalla de configuración de credenciales CGBVP

**❌ Mal (argentinismo + jerga):**
> Acá podés configurar las credenciales para activar el scraper del intranet del CGBVP. Una vez que las guardés, el sistema va a autenticarse periódicamente para jalar data.

**✅ Bien (peruano + vocabulario CGBVP):**
> Ingrese aquí su usuario y contraseña del intranet del CGBVP. El sistema los usará para descargar automáticamente el padrón de bomberos, el estado de la compañía y los partes de emergencia.
>
> Sus credenciales se guardan con cifrado. Nadie más puede verlas, ni siquiera el administrador del sistema.

### Mensaje de error al validar credenciales

**❌ Mal:**
> Auth failed. Check your credentials.

**❌ Mal (argentinismo):**
> No pudimos entrar con esos datos. Fijate que sean los que usás para entrar a bomberosperu.gob.pe.

**✅ Bien:**
> El intranet del CGBVP rechazó el usuario o la contraseña.
>
> Verifique que sean los mismos que usa para ingresar a bomberosperu.gob.pe/extranet. Si el problema persiste, puede que su contraseña haya expirado y deba cambiarla en el CGBVP.

### Confirmación de importación de inventario

**❌ Mal:**
> Dale, importamos 42 ítems. ¡Listo!

**✅ Bien:**
> Se importaron 42 ítems al inventario de la Sección de Máquinas.
>
> Puede ver los ítems cargados en el listado. Si necesita corregir algo, puede editar cada ítem individualmente o importar un nuevo archivo Excel.

### Alerta de vencimiento de EPP

**❌ Mal:**
> Ojo, al Subteniente Pérez se le vence el traje.

**✅ Bien:**
> **Alerta de vida útil:**
>
> El chaquetón estructural asignado al Subteniente Pérez Valdivia (código A23118) cumple su vida útil de 10 años el 15 de junio de 2026.
>
> Coordine la reposición con la Sección de Servicios Generales.

## 5. Qué hacer cuando no hay término oficial

Si una funcionalidad del sistema no tiene correlato en el RIF o las NDR (por ejemplo, "notificaciones push", "sincronización automática", "dashboard"):

1. Buscar la descripción funcional más simple en español peruano:
   - "notificación push" → **aviso automático**
   - "sincronización automática" → **descarga automática de datos**
   - "dashboard" → **resumen de actividad** / **panel principal**
   - "backup" → **copia de seguridad**
   - "login" → **inicio de sesión** / **ingreso al sistema**

2. Si inevitablemente hay que usar un término técnico, acompañarlo de una explicación breve la primera vez:
   > "Autenticación de dos factores (un código adicional que le enviamos a su celular al ingresar)"

3. Nunca usar anglicismos gratuitos: ❌ "toggle", "tab", "modal", "tooltip", "bug", "feature", "link"

## 7. Institucionalidad y tratamiento jerárquico

El CGBVP es una institución semi-castrense. La jerarquía, la mística y el respeto son parte esencial de su funcionamiento. El sistema debe reflejar esto sin excepción.

### Tratamiento formal con grado

**Todos los mensajes institucionales** (emails, alertas, saludos, notificaciones) tratan al usuario por **grado + apellido**:

- ✅ "Buenos días, Brigadier Herrera"
- ✅ "Seccionario Riojas, su solicitud fue registrada"
- ✅ "Capitán Vargas, tiene 3 partes de emergencia pendientes de revisión"
- ❌ "Hola María" (demasiado informal para contexto institucional)
- ❌ "Hola usuario" (impersonal)

Solo en contextos muy informales (placeholder de input, confirmación breve de acción rutinaria) se puede omitir el grado.

### Saludo variable por hora

Todo mensaje de bienvenida usa saludo según hora local (America/Lima):

| Franja horaria | Saludo |
|---|---|
| 05:00 – 11:59 | Buenos días |
| 12:00 – 18:59 | Buenas tardes |
| 19:00 – 04:59 | Buenas noches |

### Presencia del lema institucional

**"Dios-Patria-Humanidad"** es el lema oficial del CGBVP y debe estar visible en:

1. **Pantalla de login** — debajo del escudo, con tipografía secundaria pero visible
2. **Footer permanente del sistema** — siempre presente en todas las pantallas de la intranet
3. **Cabecera de documentos generados** (PDFs de partes, actas, reportes oficiales)
4. **Página pública de la compañía** (si corresponde)

No se usa como decoración superficial — es parte identitaria del CGBVP.

### Jerarquía visible en la interfaz

Donde se muestren personas, el orden y destaque siempre respeta la jerarquía:

1. **Vistas de equipo**: Primer Jefe primero, Segundo Jefe segundo, después Jefes de Sección, después Adjuntos, después efectivos por orden de grado descendente
2. **Mi Compañía / Dashboard**: los nombres del Primer y Segundo Jefe aparecen destacados, con su grado y foto (si existe)
3. **Asignaciones y permisos**: siempre con grado antepuesto: *"Asignado a: Teniente Brigadier Torres Mendoza"*
4. **Logs y auditoría**: las acciones críticas registran grado + nombre completo del actor
5. **En conflictos de permisos o aprobaciones**: el sistema respeta la cadena de mando (un Adjunto no puede aprobar algo de su Jefe de Sección, etc.)

### Denominación oficial de la compañía

Usar siempre según contexto:

| Contexto | Formato |
|---|---|
| Cabecera de login, PDFs, reportes oficiales | **Cuerpo General de Bomberos Voluntarios del Perú · Compañía N.° 163 · Ancón** |
| Header de la app, sidebar | **CGBVP · UBO 163 · Ancón** |
| Referencia breve en texto | **Compañía 163** o **UBO 163** |
| Uso interno en código | `ubo163` (slug) |

### Tono general del sistema

El CGBVP es una herramienta de trabajo seria. Los mensajes:

- Van directo al punto, sin florituras
- No usan emojis decorativos (íconos sí; emojis de sentimiento no)
- No usan animaciones juguetonas (transiciones sí, "bounces" y "wiggles" no)
- No felicitan al usuario por acciones triviales ("¡Genial!", "¡Increíble!")
- Sí reconocen el esfuerzo cuando corresponde, en tono sobrio ("Gracias por mantener actualizado el padrón")
- No infantilizan al usuario con explicaciones obvias
- Respetan el tiempo del usuario: una acción confirmada se confirma en una línea, no en un párrafo

### Elementos heráldicos

El sistema debe incorporar visualmente la identidad del CGBVP:

- El **escudo de la UBO** (en el caso de la 163, el escudo con hachas cruzadas, delfín, mar y el número 163) aparece en login, sidebar, marca de agua de cards principales
- Los **grados** se pueden representar con íconos heráldicos (divisas, estrellas según NDR Uniformes) donde corresponda
- El **dorado institucional** (color de placas y condecoraciones) se reserva para códigos oficiales (CGBVP, números de parte, números de compañía)
- El **rojo** se reserva para acciones de jerarquía mayor, alertas y el propio CGBVP como identidad primaria
